# Skill behavior acceptance scenarios

Use independent temporary cases without overwriting assets or historical runs. A fully specified non-cable case checks generality; a real case checks uncertainty handling. Format validation does not replace behavior checks. Mark unexecuted scenarios honestly.

| Input | Observable outcome |
|---|---|
| Fully specified non-cable construction request | Real Tuning and members; no repeated questions, prepare/run calls, or workspace creation |
| Same system, calibration requested | Original Tuning.run(), termination, acceptance, analysis and validation records; no repeated authorization |
| Question about the current static scorer | Explanation without a new task, loss change, or questionnaire |
| Contradictory units or clocks | Inspection or necessary question; no invented formal configuration |
| Unsupported old numerics | Pending qualification with binding/physical/refinement checks |
| Unsupported robust loss | Actual adapter gap, consistent features/fingerprint/Validator |
| Bayesian or PBT request | Check implementation/state contracts; no empty algorithm stub |
| Correlated parameters | Executed Tuning analysis or pending status; no claim that orthogonality proves identification |
| Changed frozen loss/scale/mask | New version, revised thresholds/analysis/acceptance, preserved history |
| No independent holdout | Generalization unverified; no copied or arbitrarily split acquisition |
| Authorized run with unknown critical facts | Ask only necessary facts and continue independent checks; timeout is not approval |
| Model revised after viewing holdout | Record development use and arrange fresh independent evidence |

A build-only test may make prepare/run/Environment.run fail on any call, then perform an authorized small run with a fresh object in another workspace. Record inputs, commands, status, and artifacts; distinguish format validation, manual review, execution, and independent agent behavior evaluation.
